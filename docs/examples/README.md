# Complete conversion configurations

These files contain **public dummy keys**, not credentials for a real asset.
Replace the source KIDs, keys, key URIs and associated IVs with the values for
your input. Choose new output values for your own content. Never use these
published keys to protect private media.

The `outputs/` directory contains thirteen complete schema-3 output lists.
Each file in `keys/` is a complete schema-2 `keys.json` for one named output,
including its source-key mapping when encrypted. The nine `from-clear` files
contain only output keys; the other thirty-nine include source keys.
The filename identifies the output format, output protection and input-key type.
CENC and CBCS inputs share the
`cenc-cbcs` example shape; AES-128 and TS SAMPLE-AES use separate URI mappings.
The [conversion recipes](https://kazuhide.github.io/drmr/guide/#url-input) link
the matching complete files and show the corresponding `convert` command.

Save the chosen output list as `outputs.json`. When keys are needed, save the
matching complete key file as `keys.json` outside your source and result
directories. Apply the [owner-only file permissions](../security.md) before
running the command. A clear output has an empty `outputs` object. Clear input
to clear output does not need a key file.

These generic encryption examples use `drms: []`. For explicit Widevine,
PlayReady or FairPlay information, use the complete
[multiple-output example](../multiple-outputs.md).
See the [configuration reference](../configuration.md) for field definitions.

The files are generated by `tools/conversion_examples.py`. To regenerate or
check them from the repository root:

```sh
python3 tools/conversion_examples.py
python3 tools/conversion_examples.py --check
```
