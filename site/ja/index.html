配信形式と暗号化方式を変換

MP4・DASH・HLS の形式や暗号化方式を変換する CLI です。再エンコードせず、利用者が用意した鍵を使います。

CLIから始める ソースを見る（英語）

Windows・macOS・Linux対応。ローカルWeb・Desktopは実験的な機能です。

入力と出力の対応表

完結したローカルメディアが対象です。行が入力、列が出力で、セル内は選べる出力の暗号化方式です。

横にスクロールできます。キーボードでは表に移動し、左右矢印キーで操作します。

Clear は暗号化なし。「対象外」は現在の drmr の実装範囲を示し、形式の仕様として変換できないという意味ではありません。

  1. MP4 出力は1トラック、または次の条件を満たす同じ元ファイルの映像と音声です。DASH/HLS の別々の音声・映像を、1つの MP4 に結合する出力には対応していません。
  2. MP4 には、音声の開始位置と再生時間を指定する再生情報（編集リスト）があります。エンコード時に生じる余分な音声を再生から除く場合などに使われます。同じ元ファイル内の AAC-LC 音声1本と、任意の H.264 映像1本を持つ対応範囲内のプログレッシブ MP4 は、Clear・cenc・cbcs 入力から表内の MP4・DASH・fMP4 HLS に変換する際も、その再生範囲を保ちます。複雑な編集や、入力の DRM 初期化情報は対象外です。暗号化情報の構造と検証条件の詳細は、対応範囲のドキュメントに記載しています。
  3. TS 入力は、プログレッシブ H.264 映像と 48 kHz AAC-LC 音声の限定的な構成が対象です。音声のみの場合は DASH と TS を出力できます。映像と音声がある TS 出力は、別々のプレイリストになります。

MP4 はメディアを格納する形式です。DASH（Dynamic Adaptive Streaming over HTTP）と HLS（HTTP Live Streaming）は、メディアの区間をマニフェストやプレイリストで記述します。fMP4 はフラグメント化 MP4、MPEG-TS はトランスポートストリームです。

cenc はカウンターモードによるサンプル暗号化、cbcs は CBC（暗号ブロック連鎖）によるパターン暗号化です。AES-128 は HLS リソース全体を、SAMPLE-AES は TS 内の指定部分を暗号化します。DRMライセンスの取得や端末での再生可否は、別途確認が必要です。

対応範囲と制約を読む（英語）

HLSのURLから始める場合

URLから取得できるのは、完結した非暗号化HLSだけです。--download-dirは必須です。原本を保存し、オフラインでの再実行や独立した検証に使います。リモートMP4/DASH・暗号化メディアのURL・ライブ入力・バイト範囲を指定したプレイリストは、この取得機能の対象外です。

URLから変換し、原本を残す（英語）

記載内容を調べて、実データを確かめる

まず記載された情報を調べ、対応する変換経路を計画してから実データを処理します。独立した検証のために原本を残してください。

  1. 1

    調べる

    ローカルMP4のメタデータやDASH/HLSの記載内容を読みます。メディアサンプルの確認は、変換・検証時に行います。

    drmr inspect source.mpd
  2. 2

    計画する

    変換の選択肢と必要なツールを確認します。実際のメディアと鍵は、変換時に確認します。

    drmr plan source.mpd \
  --to cbcs --format dash
  3. 3

    変換する

    入力条件を満たすメディアを再パッケージし、結果を出力として確定する前に原本と比較します。

    drmr convert source.mpd \
  --to cbcs --format dash \
  --output converted \
  --keys-file keys.json
  4. 4

    比較して検証する

    原本と、入力・出力それぞれの鍵を使って、独立した比較を行います。

    drmr verify converted/manifest.mpd \
  --source source.mpd \
  --keys-file keys.json --json

この例は、対応するDASHからCBCS DASHへの変換です。所有者だけが読める鍵設定ファイルを用意してください（英語）。鍵の値をコマンド引数やバージョン管理に残さないでください。

原本と比べる4つの確認

実際のメディアについて、ストリームの設定情報、エンコード済みパケット、時刻、デコード結果の4項目を原本と比較します。

ストリームの設定情報
コーデック、トラック構成、対応範囲内の再生設定を比較します。
エンコード済みパケットの内容
配信形式や暗号化方式による差を処理したうえで、パケット内のエンコード済み映像・音声データを比較します。
各パケットの時刻
各パケットの絶対的な表示時刻・デコード時刻・継続時間を、許容誤差を設けずに比較します。
全体をデコードした映像・音声
対象のメディアを最初から最後までデコードし、得られた映像と音声を比較します。

メディアの検証で分かる範囲

メディアの検証は、用意した鍵で内容と時刻を確認するものです。DRM（デジタル著作権管理）ライセンスの取得や端末での再生は、別途テストが必要です。

処理と検証の仕組みを読む（英語）

CLIから始める

Rust 1.95以降を使ってソースからビルドします。WindowsもネイティブCLIに対応しています。PowerShell・パス・保護ファイルの扱いはWindowsガイドを参照してください。

ソースをチェックアウトしたディレクトリで実行します。

cargo install --path crates/drmr --locked
drmr --version
drmr doctor --probe --route progressive-mp4

probeはツールのバージョンと対応オプションを確認します。メディア自体を検証するものではありません。
