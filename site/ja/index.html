コンテンツ暗号化方式の相互変換

MP4・DASH・HLS の暗号化方式を相互に変換するコマンドラインツールです。Clear（暗号化なし）の入出力にも対応しています。変換に必要な鍵は利用者が用意します。出力を確定する前に、映像・音声のデータと時刻を原本全体と照合します。

CLIから始める ソースを見る（英語）

Windows・macOS・Linux に対応しています。ローカル Web コンソールとデスクトップアプリは実験的な機能です。

入力と出力の対応表

配信内容が確定したコンテンツをローカルに保存して変換します。行は入力、列は出力を表します。各セルの暗号化方式を選ぶと、その入力・出力に合ったコマンド例が開きます。例では、公開 URL からの取得、解析、計画保存、変換、検証までを説明しています。

表は横にスクロールできます。キーボードで操作する場合は表にフォーカスを移し、左右の矢印キーを使ってください。

Clear は暗号化されていない状態を指します。「対象外」は現在の drmr が対応していない組み合わせであり、形式の仕様上変換できないという意味ではありません。

  1. MP4 出力は 1 トラックのみの構成か、次項の条件を満たす同一ファイル内の映像・音声の組み合わせに対応しています。DASH/HLS で別々に配信される音声と映像を 1 つの MP4 に結合する出力には対応していません。
  2. MP4 の編集リストは音声の開始位置と再生時間を指定する情報で、エンコード時に生じる余分な音声を再生から除く場合などに使われます。対応条件を満たすプログレッシブ MP4 では、同一ファイル内の AAC-LC 音声 1 本、またはそれに H.264 映像 1 本を組み合わせた構成で編集リストを保持します。Clear・cenc・cbcs の各入力から表内の MP4・DASH・fMP4 HLS に変換する際も再生範囲を保ちます。複雑な編集や入力の DRM 初期化情報は対象外です。暗号化情報の構造と検証条件の詳細は、対応範囲のドキュメントに記載しています。
  3. TS 入力はプログレッシブ H.264 映像と 44.1 kHz または 48 kHz の AAC-LC 音声を使った限定的な構成が対象です。音声のみの入力からも DASH・fMP4 HLS・TS を出力できます。映像と音声を TS で出力する場合は、それぞれ別のプレイリストになります。

MP4 は映像や音声を格納する形式です。DASH（Dynamic Adaptive Streaming over HTTP）と HLS（HTTP Live Streaming）では、コンテンツを区間に分け、その構成をマニフェストやプレイリストに記述します。fMP4 はフラグメント化 MP4、MPEG-TS はトランスポートストリームです。

cenc はカウンターモードによるサンプル暗号化、cbcs は CBC（暗号ブロック連鎖）によるパターン暗号化です。AES-128 は HLS リソース全体を、SAMPLE-AES は TS 内の指定部分を暗号化します。DRM ライセンスの取得や端末での再生可否は別途確認が必要です。

対応範囲と制約を読む（英語）

URL を入力に使う場合

analyze URL --download-dir で、対応条件を満たす MP4・static DASH・配信が完結した HLS を取得して解析できます。DASH は、一つの Period と SegmentTemplate、有限の SegmentTimeline を持つ構成が対象です。暗号化入力には --keys-file で入力鍵を指定します。鍵 URI やライセンスは取得しません。保存した原本はオフラインでの計画・変換・再検証に使えます。詳しい条件は日本語ガイドに記載しています。ライブ、バイト範囲指定、その他の DASH 参照方式は現在の取得機能の対象外です。

URL の取得・変換手順（英語）

解析・計画・変換・検証

URL から取得したデータを解析し、変換条件を計画ファイルに保存します。そのファイルを使って変換を実行し、保存した原本と変換結果を照合します。

  1. 1

    入力の解析

    配信内容が確定した Clear HLS を取得し、対応するすべてのトラックの映像・音声データを確認します。

    drmr analyze \
  "https://example.com/vod/master.m3u8" \
  --download-dir source --json
  2. 2

    変換条件の保存

    原本のハッシュ値と変換条件を計画ファイル（plan）に保存します。変換条件には出力形式・暗号化方式・新しい出力先を含みます。

    drmr plan source/input.m3u8 \
  --to cbcs --format dash \
  --output converted \
  --save conversion.plan.json
  3. 3

    変換の実行

    計画ファイルに従って変換を実行します。鍵はこの段階で別途指定します。計画の保存後に原本のデータが変わっている場合は処理を停止します。

    drmr convert \
  --plan conversion.plan.json \
  --keys-file keys.json
  4. 4

    変換結果の検証

    出力の形式・暗号化方式を確認し、映像・音声の全データと時刻を原本と照合します。

    drmr verify \
  --plan conversion.plan.json \
  --keys-file keys.json --json

この例では、対応範囲内の Clear HLS を CBCS DASH に変換します。日本語ガイドで手順を確認し、所有者だけが読める鍵の設定ファイルを用意してください（英語）。Clear から Clear への変換では --to clear を指定し、鍵ファイルを省略できます。メタデータだけを調べる場合は inspect を使います。

対応範囲内の非暗号化 HLS（TS）から FairPlay 向け HLS と Widevine／PlayReady 向け DASH をまとめて作るには、plan --outputs outputs.json を使います。日本語ガイドでは出力ごとの形式・鍵・検査条件の指定方法を説明しています。結果はすべての検査に通った後で確定します。

最終マニフェストは内蔵の検査機能（Linter）で確認します。保存済みの出力も verify OUTPUT --manifest-only で検査できます。--external-validator を追加すると、形式に応じて Apple または DASH-IF のツールでも検査します。マニフェストの検査結果と原本全体とのメディア比較結果は分けて表示します。

原本との比較項目

ストリームの設定情報、エンコード済みパケットの内容、時刻、デコード結果の 4 項目で原本と変換結果を比較します。

ストリームの設定情報
コーデック、トラック構成、対応範囲内の再生設定を比較します。
エンコード済みパケットの内容
配信形式や暗号化方式による差を処理したうえで、パケット内のエンコード済み映像・音声データを比較します。
各パケットの時刻
各パケットの絶対的な表示時刻・デコード時刻・継続時間を許容誤差なしで比較します。
全体をデコードした映像・音声
対象のメディアを最初から最後までデコードし、得られた映像と音声を比較します。

メディアの検証で分かる範囲

メディアの検証では利用者が用意した鍵で内容と時刻を確認します。DRM（デジタル著作権管理）ライセンスの取得や端末での再生は別途テストが必要です。

処理と検証の仕組みを読む（英語）

CLI のインストール

Rust 1.95 以降を使ってソースからビルドします。Windows でも CLI を直接実行できます。PowerShell の使い方、パスや保護されたファイルの扱いは Windows ガイドを参照してください。

利用する配布物のプレリリース表示と説明を確認してください。対応条件と検証範囲はリリースと互換性（英語）に記載しています。

ソースをチェックアウトしたディレクトリで実行します。

cargo install --path crates/drmr --locked
drmr --version
drmr doctor --probe --route progressive-mp4

doctor --probe は外部ツールのバージョンと対応オプションを確認します。メディア自体の検証は行いません。
