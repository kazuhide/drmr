配信メディアの変換と比較検証

drmrは、対応条件を満たすオンデマンド配信（VOD）のメディアを対象に、配信形式や暗号化方式を変換します。映像・音声の再エンコードは行いません。変換したメディアは、原本と比較して検証します。

暗号化メディアには、利用者が用意した鍵を使います。入力の復号と出力の暗号化は別々の鍵設定として扱います。管理する権限のあるメディアを対象としてください。

始める ソースを見る（英語）

Windows・macOS・Linuxで動くネイティブCLI（コマンドラインツール）です。
ローカルWeb・Desktopインターフェースは実験的な機能です。

記載内容を調べて、実データを確かめる

まず記載された情報を調べ、対応する変換経路を計画してから実データを処理します。独立した検証のために原本を残してください。

  1. 1

    調べる

    ローカルMP4のメタデータやDASH/HLSの記載内容を読みます。メディアサンプルの確認は、変換・検証時に行います。

    drmr inspect source.mpd
  2. 2

    計画する

    変換の選択肢と必要なツールを確認します。実際のメディアと鍵は、変換時に確認します。

    drmr plan source.mpd \
  --to cbcs --format dash
  3. 3

    変換する

    入力条件を満たすメディアを再パッケージし、新しい出力を保存する前に原本と比較します。

    drmr convert source.mpd \
  --to cbcs --format dash \
  --output converted \
  --keys-file keys.json
  4. 4

    比較して検証する

    原本と、入力・出力それぞれの鍵を使って、独立した比較を行います。

    drmr verify converted/manifest.mpd \
  --source source.mpd \
  --keys-file keys.json --json

この例は、対応するDASHからCBCS DASHへの変換です。所有者だけが読める鍵設定ファイルを用意してください（英語）。鍵の値をコマンド引数やバージョン管理に残さないでください。

コンテナ形式で対応範囲が変わる

MP4はメディアを格納する形式です。DASH（Dynamic Adaptive Streaming over HTTP）とHLS（HTTP Live Streaming）は、マニフェストやプレイリストでメディアの区間を記述します。HLSはフラグメント化MP4（fMP4）やMPEGトランスポートストリーム（MPEG-TS）を扱えます。

MP4

音声または映像の単独トラックに対応します。AAC音声とH.264映像（映像は省略可）を扱う別の入力条件もあります。出力の制限は対応表を確認してください。

DASH

対応条件を満たす、fMP4トラックを使った静的な配信データが対象です。非暗号化（clear）・cenc・cbcsの変換経路に対応します。

HLS / フラグメント化MP4

対応するfMP4トラックを含む、完結したローカルプレイリストが対象です。非暗号化・CBCS・リソース全体を暗号化するAES-128出力に対応します。

HLS / MPEG-TS

H.264/AACに限定した、より狭い対応範囲です。非暗号化・AES-128・SAMPLE-AESのTS変換経路と、条件を満たすfMP4 HLS出力に対応します。

cencはカウンターモードでサンプルを暗号化します。cbcsはCBC（暗号ブロック連鎖）によるパターン暗号化です。HLS AES-128はリソース全体を、SAMPLE-AES TSはメディア内の指定部分を暗号化します。DRMライセンスの取得や端末での再生可否は、これらの暗号化方式とは別に確認する項目です。

対応範囲と制約を読む（英語）

HLSのURLから始める場合

URLから取得できるのは、完結した非暗号化HLSだけです。--download-dirは必須です。原本を保存し、オフラインでの再実行や独立した検証に使います。リモートMP4/DASH・暗号化メディアのURL・ライブ入力・バイト範囲を指定したプレイリストは、この取得機能の対象外です。

URLから変換し、原本を残す（英語）

原本と比べる4つの確認

実際のメディアについて、ストリームの設定情報、エンコード済みパケット、時刻、デコード結果の4項目を原本と比較します。

ストリームの設定情報
コーデック、トラック構成、対応範囲内の再生設定を比較します。
エンコード済みパケットの内容
配信形式や暗号化方式による差を処理したうえで、パケット内のエンコード済み映像・音声データを比較します。
各パケットの時刻
各パケットの絶対的な表示時刻・デコード時刻・継続時間を、許容誤差を設けずに比較します。
全体をデコードした映像・音声
対象のメディアを最初から最後までデコードし、得られた映像と音声を比較します。

メディアの検証で分かる範囲

メディアの検証は、用意した鍵で内容と時刻を確認するものです。DRM（デジタル著作権管理）ライセンスの取得や端末での再生は、別途テストが必要です。

処理と検証の仕組みを読む（英語）

CLIから始める

Rust 1.95以降を使ってソースからビルドします。WindowsもネイティブCLIに対応しています。PowerShell・パス・保護ファイルの扱いはWindowsガイドを参照してください。

ソースをチェックアウトしたディレクトリで実行します。

cargo install --path crates/drmr --locked
drmr --version
drmr doctor --probe --route progressive-mp4

probeはツールのバージョンと対応オプションを確認します。メディア自体を検証するものではありません。
